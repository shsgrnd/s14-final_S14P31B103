# AI 모델 성능 평가 지표 가이드 (Phase 3)

본 문서는 `eval_fixed.jsonl` 테스트 셋을 기준으로 **Base vs SFT vs DPO** 모델의 성능을 비교 분석하기 위한 정량/정성 평가 항목을 정의합니다.

## 1. 정량 평가 항목 (`eval_fixed.jsonl` 자동 스코어링)

`eval_fixed.jsonl`에 포함된 정답(Ground Truth)과 모델의 추론 결과를 파이프라인 스크립트로 비교하여 자동 스코어를 산출합니다.

*   **포맷 준수율 (Format Adherence Rate)**
    *   **정의:** 모델이 요구된 JSON 스키마 구조(예: `explanation`, `patch` 필드 등)를 정확히 준수하여 출력했는지 확인.
    *   **측정 방법:** 파싱 성공 횟수 / 전체 테스트 케이스 수 (100% 목표)
*   **코드 유사도 (Code Similarity: BLEU / ROUGE-L)**
    *   **정의:** 정답 패치(Patch) 또는 해결 코드와 생성된 코드 간의 텍스트 유사도.
    *   **주의점:** 코드는 단어의 순서가 중요하므로 엄격한 유사도 측정 지표로 활용하되, 로직이 동일하지만 구현이 다른 경우는 정성 평가로 보완.

## 2. 정성 평가 항목 (휴먼 평가 또는 LLM-as-a-Judge)

정량적 지표가 잡아내지 못하는 논리적 완결성과 사용자 친화도를 **5점 척도(1~5점)** 로 세밀하게 평가합니다.

### 2.1. 해결 정확도 (Resolution Accuracy)
*   **설명:** 충돌의 근본 원인을 파악하고 논리적으로 올바른 해결 코드를 제시하였는가?
*   **채점 기준:**
    *   **5점:** 완벽한 해결책을 제시하며, 주변 코드와의 맥락도 완벽히 호환됨.
    *   **3점:** 충돌은 해결되나, 최적의 코드는 아님 (예: 불필요한 주석 포함, 비효율적 로직).
    *   **1점:** 충돌 해결에 실패하거나 코드 문법이 깨짐.

### 2.2. 설명 일관성 (Explanation Consistency)
*   **설명:** 제시한 해결 코드(`patch`)와 자연어 설명(`explanation`)의 내용이 일치하는가?
*   **채점 기준:**
    *   **5점:** 수정된 코드 라인별로 왜 그렇게 수정했는지 명확하고 일관되게 설명함.
    *   **3점:** 설명이 모호하거나 너무 짧아 코드의 의도를 절반 정도만 이해할 수 있음.
    *   **1점:** 설명과 코드가 전혀 딴판이거나 앞뒤가 맞지 않는 소리를 함.

### 2.3. 포맷 안정성 (Format Stability)
*   **설명:** JSON 구조 외에도, Markdown 코드 블록이나 불필요한 프롬프트 잔여물(예: `<think>` 태그)이 섞여 있지 않은가?
*   **채점 기준:**
    *   **5점:** 파싱을 방해하는 어떠한 불순물도 없이 깔끔한 결과물만 출력됨.
    *   **3점:** 마크다운 태그 등 제거 가능한 불순물이 섞여 있으나 정규식 처리로 복구 가능.
    *   **1점:** 포맷이 완전히 무너져 파싱이 불가능함.

### 2.4. 과도한 추론 여부 (Over-reasoning / Hallucination)
*   **설명:** 주어진 충돌 파일 범위 외의 내용을 멋대로 지어내거나(Hallucination), 묻지 않은 장황한 설명을 덧붙이는가?
*   **채점 기준:**
    *   **5점:** 필요한 설명만 간결하게 핵심 위주로 답변함.
    *   **3점:** 다소 장황하지만 사실과 다르지는 않음.
    *   **1점:** 파일에 존재하지 않는 변수나 함수를 언급하며 심각한 환각 증세를 보임.

## 3. 평가 진행 파이프라인 가이드

1.  **추론 (Inference):** Base, SFT, DPO 세 가지 모델 각각에 대해 `eval_fixed.jsonl`을 인풋으로 하여 결과를 생성합니다.
2.  **자동 채점 (Auto-scoring):** 파서(Parser)를 이용해 포맷 준수율을 계산하고, 파이썬 스크립트를 통해 BLEU/ROUGE 스코어를 산출합니다.
3.  **수동/정성 평가 (Manual Review):** 정성 평가 항목(해결 정확도, 설명 일관성 등)에 따라 팀원들이 블라인드 테스트 방식으로 채점합니다.
4.  **결과 비교표 작성:** 문서화된 기준에 따라 `Base vs SFT vs DPO 결과 비교표`를 작성하여 DPO의 성능 향상 효과를 입증합니다.
