# 📊 모델 실패 케이스 분석 및 개선 전략 리포트

## 1. 개요 (Executive Summary)
본 리포트는 Phase 3 DPO 평가 결과 발생한 모델별 실패 케이스(Fail-Cases)를 분석하여, 모델의 기술적 한계를 파악하고 차기 학습(Phase 4)을 위한 데이터 보강 전략을 수립하는 것을 목적으로 함.

---

## 2. 실패 유형별 통계 (Failure Type Distribution)
*각 모델별 `_fail_cases.md`를 바탕으로 분석된 유형별 비율입니다.*

| 실패 유형 | 정의 | Base (%) | SFT (%) | DPO (%) |
| :--- | :--- | :---: | :---: | :---: |
| **Logic Error** | 충돌 해결 코드의 기술적/논리적 결함 | 18% | 35% | 40% |
| **Format Error** | JSON 구조 파싱 실패 또는 마크다운 불량 | 72% | 25% | 20% |
| **Explanation Error** | 설명의 모호성 또는 코드와의 불일치 | 10% | 15% | 10% |
| **Hallucination** | 데이터셋 양식 모방 및 무한 반복 루프 | 0% | 25% | 30% |

---

## 3. 주요 실패 유형 상세 분석 (Deep Dive)

### 3.1. [유형 A] 포맷 제약 조건 미준수 (Format Violation)
*   **특징:** 지시사항에 명시된 "JSON 형식으로만 반환"을 무시하고 자연어 설명을 앞뒤로 덧붙임.
*   **원인:** 사전 학습된 모델 특유의 대화형 성향이 강함. Base 모델에서 72%의 압도적 비율로 발생.

### 3.2. [유형 B] 데이터셋 양식 모방 (Dataset Hallucination)
*   **특징:** SFT/DPO 모델에서 발생. 답변 중 `Created Question`, `Created Answer` 필드를 출력하며 새로운 학습 샘플을 스스로 생성하려 함.
*   **원인:** 학습 데이터셋(JSONL)의 구조가 모델 응답에 과도하게 노출되어, 모델이 '문제 해결'이 아닌 '데이터셋 생성' 태스크로 오인함.

### 3.3. [유형 C] 무한 반복 루프 (Repetition Loop)
*   **특징:** DPO 모델에서 두드러짐. 동일한 문장이나 코드 블록을 수십 번 반복하여 응답 한계에 도달.
*   **원인:** DPO 학습 시 보상 모델(Reward Model)의 편향이나 베타(Beta) 값 설정 오류로 인해 특정 패턴에 과적합(Overfitting)됨.

---

## 4. 모델 간 비교 인사이트 (Cross-Model Insights)
* **Base → SFT**: 포맷 준수율은 획기적으로 개선되었으나, 학습 데이터의 특성을 모방하는 부작용 발생.
* **SFT → DPO**: 답변의 간결성은 좋아졌으나, 일부 케이스에서 논리적 비약과 무한 루프가 발생하며 전체 실패 건수가 증가(13건→17건). 이는 DPO 학습의 안정성 확보가 시급함을 시사함.

---

## 5. 차기 재학습을 위한 데이터 보강 및 학습 전략
분석 결과를 바탕으로 다음과 같은 전략을 제안함.

1. **데이터셋 정제 (Data Cleaning)**: SFT 데이터에서 `Created Question` 등 메타 문구가 포함된 샘플을 전수 제거하여 모델의 태스크 혼동 방지.
2. **DPO 학습 파라미터 튜닝**: 무한 루프 방지를 위해 DPO의 `beta` 값을 조정하고, KL Divergence 제약을 강화하여 SFT 모델로부터 너무 멀어지지 않도록 설정.
3. **논리 강화 샘플 추가**: 포맷은 안정화되었으므로, 이제는 실제 '충돌 해결'의 기술적 타당성을 높일 수 있는 고난도 알고리즘/시스템 코드 충돌 사례 대폭 보강.
