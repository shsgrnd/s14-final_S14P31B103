## TEST-01: 변수명 선언 키워드 중복 수정

### 📥 Input
```text
Ours: const a = 1; 
Theirs: let a = 1; 
Base: var a = 1;
```

### 🤖 AI Answer
주어진 충돌 상황을 분석해보겠습니다.

---

### 상황 정리

- **Base (공통 조상)**:  
  ```js
  var a = 1;
  ```
- **Ours (내 변경사항)**:  
  ```js
  const a = 1;
  ```
- **Theirs (상대 변경사항)**:  
  ```js
  let a = 1;
  ```

---

### 충돌 원인 분석

- Base에서는 `var` 키워드를 사용해 변수를 선언했습니다.
- Ours에서는 `const`로 변경했고, Theirs에서는 `let`으로 변경했습니다.
- `var`, `let`, `const`는 모두 변수 선언 키워드지만, 스코프와 재할당 가능 여부가 다릅니다.
- `var`는 함수 스코프, `let`과 `const`는 블록 스코프입니다.
- `const`는 재할당이 불가능한 상수 선언이고, `let`은 재할당 가능한 변수 선언입니다.
- 따라서 Ours와 Theirs는 변수 선언 방식과 재할당 가능성에 대해 서로 다르게 변경한 상태입니다.
- Git은 이 차이를 자동으로 병합할 수 없기 때문에 충돌이 발생했습니다.

---

### 해결책 제시

1. **의도 파악**  
   - 변수 `a`가 재할당될 가능성이 있는지 확인합니다.
   - 만약 `a`가 변경되지 않는 값이라면 `const`가 적합합니다.
   - 만약 `a`가 이후에 재할당된다면 `let`을 사용해야 합니다.

2. **코드 스타일 일관성 유지**  
   - 프로젝트 내에서 변수 선언 시 `var` 대신 `let`과 `const`를 사용하는 것이 권장됩니다.
   - 가능하면 `const`를 기본으로 하고, 재할당이 필요한 경우에만 `let`을 사용합니다.

3. **충돌 해결 예시**  
   - `a`가 상수라면:
     ```js
     const a = 1;
     ```
   - `a`가 재할당될 수 있다면:
     ```js
     let a = 1;
     ```

4. **추가 점검**  
   - `a`가 사용되는 코드 전체를 검토하여 재할당 여부를 확인합니다.
   - 필요하면 팀원과 협의하여 선언 방식을 결정합니다.

---

### 요약

| 키워드 | 스코프       | 재할당 가능성 | 권장 사용 상황                  |
|--------|--------------|---------------|-------------------------------|
| var    | 함수 스코프  | 가능          | 레거시 코드, 호이스팅 필요 시 |
| let    | 블록 스코프  | 가능          | 재할당이 필요한 변수           |
| const  | 블록 스코프  | 불가능        | 변경되지 않는 상수             |

---

필요하면 충돌 마커를 제거하고 위 기준에 따라 선언문을 수정하여 병합하세요.

## TEST-02: 동일 함수 내 로직 충돌

### 📥 Input
```text
Ours: function add(a, b) { return a + b + 1; } 
Theirs: function add(a, b) { return a + b + 2; } 
Base: function add(a, b) { return a + b; }
```

### 🤖 AI Answer
주어진 충돌 상황을 분석해보겠습니다.

---

### 1. 상황 분석

- **Base** (기본 버전):  
  ```js
  function add(a, b) { return a + b; }
  ```
  - 두 수를 더하는 기본 함수입니다.

- **Ours** (내 로컬 변경):  
  ```js
  function add(a, b) { return a + b + 1; }
  ```
  - 기본 함수에 `+1`을 추가했습니다.

- **Theirs** (상대방 변경):  
  ```js
  function add(a, b) { return a + b + 2; }
  ```
  - 기본 함수에 `+2`를 추가했습니다.

---

### 2. 충돌 원인

- **동일한 함수 `add`를 서로 다르게 수정**했습니다.
- Base에서는 단순 덧셈이었는데, Ours는 결과에 1을 더하고, Theirs는 2를 더하는 변경이 충돌을 일으킵니다.
- Git은 어떤 변경을 선택해야 할지 판단할 수 없기 때문에 충돌이 발생합니다.

---

### 3. 해결책 제시

- **기능적 요구사항에 따라 결정**해야 합니다.
- 예를 들어, 결과에 1을 더할지 2를 더할지, 혹은 다른 로직을 적용할지 팀과 협의가 필요합니다.

#### 해결 방법 예시

1. **Ours 선택** (결과에 +1 추가):
   ```js
   function add(a, b) { return a + b + 1; }
   ```

2. **Theirs 선택** (결과에 +2 추가):
   ```js
   function add(a, b) { return a + b + 2; }
   ```

3. **새로운 로직으로 합침** (예: +3 추가):
   ```js
   function add(a, b) { return a + b + 3; }
   ```

4. **기본 로직 유지** (변경사항 무시):
   ```js
   function add(a, b) { return a + b; }
   ```

---

### 4. 요약

- 충돌은 같은 함수의 반환값을 다르게 수정해서 발생했습니다.
- 팀과 상의하여 어떤 변경을 반영할지 결정하세요.
- 결정 후 충돌 코드를 수정하고 커밋하면 됩니다.

필요하면 더 구체적인 해결 방안도 도와드릴게요!
