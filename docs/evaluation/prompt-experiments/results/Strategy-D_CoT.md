## TEST-01: 변수명 선언 키워드 중복 수정

### 📥 Input
```text
Ours: const a = 1; 
Theirs: let a = 1; 
Base: var a = 1;
```

### 🤖 AI Answer
1. Base 대비 각 브랜치의 변경 의도 파악  
- Base: `var a = 1;`  
- Ours: `const a = 1;`  
  - 의도: 변수 `a`를 상수로 선언하여 재할당을 방지하고, 블록 스코프를 적용하려는 의도.  
- Theirs: `let a = 1;`  
  - 의도: 변수 `a`를 재할당 가능하지만 블록 스코프를 가지는 변수로 선언하려는 의도.  

2. 두 변경 사항이 충돌하는 기술적 이유 도출  
- `const`와 `let`은 모두 ES6에서 도입된 블록 스코프 변수 선언 방식이지만, `const`는 재할당 불가, `let`은 재할당 가능.  
- 따라서 두 브랜치가 변수의 재할당 가능 여부에 대해 상반된 의도를 가지고 있음.  
- 이로 인해 충돌 발생: 하나는 상수 선언, 다른 하나는 재할당 가능한 변수 선언.  

3. 최적의 중재안 생성  
- 변수 `a`가 실제 코드에서 재할당되는지 확인하는 것이 우선.  
- 만약 재할당이 없다면 `const`를 사용하는 것이 더 안전하고 권장되는 방식.  
- 재할당이 필요한 경우 `let`을 사용해야 함.  
- 따라서:  
  - 재할당 여부 확인 후, 재할당 없으면 `const a = 1;` 채택  
  - 재할당 필요하면 `let a = 1;` 채택  
- 만약 재할당 여부를 알 수 없거나 불명확하다면, 일단 `let`으로 두고 추후 코드 리뷰를 통해 상수화 여부 결정 권장.

## TEST-02: 동일 함수 내 로직 충돌

### 📥 Input
```text
Ours: function add(a, b) { return a + b + 1; } 
Theirs: function add(a, b) { return a + b + 2; } 
Base: function add(a, b) { return a + b; }
```

### 🤖 AI Answer
1. Base 대비 각 브랜치의 변경 의도 파악  
- Base: 기본 함수는 두 인자 a와 b를 더해서 반환한다.  
- Ours: 기존 합에 1을 더해 반환한다. 즉, 결과를 +1 증가시키는 의도.  
- Theirs: 기존 합에 2를 더해 반환한다. 즉, 결과를 +2 증가시키는 의도.  

2. 두 변경 사항이 충돌하는 기술적 이유 도출  
- 두 브랜치 모두 함수의 반환값을 변경했으나, 더하는 상수값이 다르다.  
- 충돌은 함수의 반환값이 다르게 정의되어 있어 어느 쪽을 선택할지 결정해야 하는 상황이다.  
- 기술적으로는 단순한 숫자 차이지만, 의미적으로는 결과값이 달라지는 중요한 변경이다.  

3. 최적의 중재안 생성  
- 중재안은 두 변경 의도를 모두 반영하거나, 프로젝트 요구사항에 맞게 조정해야 한다.  
- 예를 들어, 두 변경을 합쳐서 +3을 더하는 방법이 있다: return a + b + 3;  
- 또는, 함수 호출 맥락을 고려해 어느 쪽이 더 적합한지 판단 후 선택한다.  
- 만약 두 변경이 독립적인 이유로 각각 필요하다면, 함수 시그니처를 변경해 옵션을 추가할 수도 있다. 예:  
  ```javascript
  function add(a, b, increment = 0) { return a + b + increment; }
  ```  
- 기본적으로는 프로젝트 요구사항과 팀 합의를 통해 결정하는 것이 최선이다.  

요약:  
- Base는 a+b 반환  
- Ours는 a+b+1 반환  
- Theirs는 a+b+2 반환  
- 충돌은 반환값 상수 차이  
- 중재안: a+b+3 반환하거나, 함수에 증분 인자를 추가해 유연하게 처리하는 방법 추천.
