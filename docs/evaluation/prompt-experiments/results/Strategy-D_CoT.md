## TEST-01: 변수명 선언 키워드 중복 수정

### 📥 Input
```text
Ours: const a = 1; 
Theirs: let a = 1; 
Base: var a = 1;
```

### 🤖 AI Answer
1. Base 대비 각 브랜치의 변경 의도 파악  
- Base: `var a = 1;`  
- Ours: `const a = 1;` → 변수 `a`를 상수로 선언하여 재할당을 방지하려는 의도  
- Theirs: `let a = 1;` → 변수 `a`를 블록 스코프를 가지는 변수로 선언하여 재할당 가능하도록 하려는 의도  

2. 두 변경 사항이 충돌하는 기술적 이유 도출  
- `const`는 재할당이 불가능한 상수 선언이고, `let`은 재할당 가능한 변수 선언이다.  
- 따라서 `const`와 `let`은 변수 재할당 가능 여부에서 상반된 의미를 가진다.  
- 충돌의 핵심은 변수 `a`가 재할당 가능한지 여부에 대한 의도 차이이다.  

3. 최적의 중재안 생성  
- 변수 `a`가 재할당되지 않는다면 `const`를 사용하는 것이 더 안전하고 권장된다.  
- 만약 코드 내에서 `a`가 재할당된다면 `let`을 사용해야 한다.  
- 따라서 코드 전체를 검토하여 `a`가 재할당되는지 확인하는 것이 우선이다.  
- 재할당이 없다면 `const a = 1;`으로 합치고, 재할당이 있다면 `let a = 1;`으로 합친다.  
- 만약 재할당 여부를 알 수 없거나 혼재되어 있다면, 안전하게 `let a = 1;`으로 합치는 것이 무난하다.  

요약:  
- 재할당 없음 → `const a = 1;`  
- 재할당 있음 또는 불확실 → `let a = 1;`

## TEST-02: 동일 함수 내 로직 충돌

### 📥 Input
```text
Ours: function add(a, b) { return a + b + 1; } 
Theirs: function add(a, b) { return a + b + 2; } 
Base: function add(a, b) { return a + b; }
```

### 🤖 AI Answer
1. Base 대비 각 브랜치의 변경 의도 파악  
- Base: 기본 함수는 두 인자 a와 b를 더하는 단순한 덧셈 함수  
- Ours: 결과에 +1을 추가하여 a + b + 1을 반환  
- Theirs: 결과에 +2를 추가하여 a + b + 2를 반환  

두 브랜치 모두 기본 덧셈 결과에 상수를 더하는 의도로 변경함. 다만 Ours는 +1, Theirs는 +2를 더함.

2. 두 변경 사항이 충돌하는 기술적 이유 도출  
- 함수 시그니처와 기본 로직은 동일하나, 반환값에 더하는 상수 값이 다름  
- 병합 시 어떤 상수를 더할지 결정해야 하므로 충돌 발생  
- 기술적으로는 단순한 숫자 차이지만, 의미적으로는 결과값이 달라지는 중요한 차이  

3. 최적의 중재안 생성  
- 중재안은 두 변경 의도를 모두 고려하여 함수의 목적과 요구사항에 맞게 결정해야 함  
- 만약 두 변경 모두 의미 있는 보정값이라면, 합산하거나 파라미터로 조정 가능  
- 예: 함수에 옵션 파라미터를 추가하여 보정값을 외부에서 지정하도록 변경  

중재안 예시:  
```javascript
function add(a, b, offset = 0) {
  return a + b + offset;
}
```

- 기존 호출부에서 offset을 1 또는 2로 지정 가능  
- 이렇게 하면 Ours와 Theirs의 요구를 모두 수용 가능  
- 만약 offset 기본값을 1 또는 2로 정할지 팀과 협의 필요  

또는, 두 상수의 의미를 명확히 파악 후 하나로 통일하는 것도 방법임.
