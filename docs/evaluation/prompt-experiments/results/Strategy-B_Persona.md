## TEST-01: 변수명 선언 키워드 중복 수정

### 📥 Input
```text
Ours: const a = 1; 
Theirs: let a = 1; 
Base: var a = 1;
```

### 🤖 AI Answer
안녕하세요! Git 충돌 상황에서 발생한 코드를 보니, `const a = 1;` (Ours), `let a = 1;` (Theirs), 그리고 `var a = 1;` (Base) 세 가지 버전이 충돌한 상태입니다.

### 기술적 원인 분석
1. **변수 선언 키워드 차이**  
   - Base 버전은 `var`로 변수를 선언했습니다. `var`는 함수 스코프(function-scoped)를 가지며, 호이스팅(hoisting)의 영향을 받습니다.
   - Ours는 `const`를 사용했는데, `const`는 블록 스코프(block-scoped)를 가지며, 재할당이 불가능한 상수 선언입니다.
   - Theirs는 `let`을 사용했는데, `let`도 블록 스코프를 가지며, 재할당은 가능하지만 재선언은 불가능합니다.

2. **코드 의도 및 변경 방향**  
   - Base에서 `var`를 사용하다가 Ours 쪽에서는 상수 선언(`const`)으로 변경한 것은 변수의 값이 변하지 않음을 명확히 하려는 의도일 수 있습니다.
   - Theirs 쪽에서는 `let`으로 변경했는데, 이는 변수의 값이 변경될 가능성을 염두에 둔 선언입니다.

3. **충돌 발생 이유**  
   - Git은 같은 위치에서 서로 다른 키워드(`var` vs `let` vs `const`)를 사용한 변경을 자동으로 병합하지 못합니다.
   - 이는 단순한 텍스트 차이뿐 아니라, 변수의 스코프와 재할당 가능성에 영향을 주는 중요한 변경이기 때문에 충돌로 처리됩니다.

### 해결 방법 제안
- **변수 사용 의도를 명확히 파악**하세요. 해당 변수 `a`가 이후에 재할당되는지, 혹은 상수로 유지되어야 하는지 확인이 필요합니다.
- 만약 값이 변하지 않는다면 `const`를 사용하는 것이 좋고, 변경 가능성이 있다면 `let`을 선택하세요.
- 팀 내 코딩 컨벤션이나 스타일 가이드가 있다면 그에 맞춰 결정하는 것도 중요합니다.

### 요약
- 충돌은 `var`, `let`, `const`라는 서로 다른 변수 선언 키워드 사용으로 발생했습니다.
- 각 키워드는 스코프와 재할당 가능성에서 차이가 있어 Git이 자동 병합하지 못합니다.
- 변수 사용 목적에 따라 적절한 키워드를 선택해 충돌을 수동으로 해결해야 합니다.

필요하면 충돌 해결 과정에서 도움을 드릴 수 있으니 언제든 문의 주세요!

## TEST-02: 동일 함수 내 로직 충돌

### 📥 Input
```text
Ours: function add(a, b) { return a + b + 1; } 
Theirs: function add(a, b) { return a + b + 2; } 
Base: function add(a, b) { return a + b; }
```

### 🤖 AI Answer
안녕하세요! 주신 세 가지 버전의 코드를 보면, Git에서 발생한 충돌 상황을 이해하는 데 도움이 됩니다.

- **Base**: `function add(a, b) { return a + b; }`  
  원래의 공통 조상(기준) 버전입니다.

- **Ours**: `function add(a, b) { return a + b + 1; }`  
  현재 브랜치에서 수정한 내용입니다.

- **Theirs**: `function add(a, b) { return a + b + 2; }`  
  병합 대상 브랜치에서 수정한 내용입니다.

---

### 충돌의 기술적 원인

두 브랜치 모두 `add` 함수의 반환값을 변경했지만, 서로 다른 방식으로 변경했습니다. 즉, 같은 코드 라인(함수 내부의 `return` 문)을 각각 다르게 수정했기 때문에 Git이 자동으로 어느 쪽을 선택해야 할지 판단할 수 없습니다.

- **Ours**는 `a + b + 1`로 변경했고,
- **Theirs**는 `a + b + 2`로 변경했습니다.

이처럼 동일한 코드 영역을 서로 다르게 수정하면 Git은 자동 병합이 불가능하며, 충돌(conflict) 상태가 됩니다.

---

### 해결 방법 제안

1. **코드 의도 파악**  
   두 변경사항 중 어떤 것이 올바른지, 혹은 두 변경사항을 조합해야 하는지 팀 내에서 의도를 확인하세요.

2. **수동 병합**  
   충돌 난 부분을 직접 편집하여 원하는 최종 코드를 작성합니다. 예를 들어:

   ```javascript
   function add(a, b) {
       return a + b + 1; // 혹은 a + b + 2, 또는 a + b + 3 등
   }
   ```

3. **테스트 및 검증**  
   병합 후에는 반드시 기능 테스트를 수행해 의도한 동작이 맞는지 확인하세요.
