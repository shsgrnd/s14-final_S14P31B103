# Evaluation Metrics Specification (Phase 1)

본 문서는 GitCat AI 모델의 SFT(Fine-tuning) 및 DPO 학습 성과를 정량적으로 측정하기 위한 평가 지표를 정의합니다.

## 1. 평가 목적
- 학습 전(Base Model)과 학습 후(SFT/DPO Model)의 성능 차이를 객관적 수치로 비교
- 프롬프트 엔지니어링 및 데이터 정제 작업의 유효성 검증
- 실제 서비스 적용 가능 여부를 판단하는 최종 기준으로 활용

---

## 2. 핵심 평가 지표 (Core Metrics)

### [지표 1] Pass@1 (정확도)
- **정의**: 모델에게 동일한 문제를 1번 풀게 했을 때, 정답을 맞힌 비율
- **측정 방법**:
  - AI가 생성한 '해결 코드'가 문법적 오류가 없는가?
  - 제안된 해결책이 충돌 상황의 기술적 모순을 해결했는가? (Pass/Fail)
- **목표**: 서비스 배포를 위한 최소 기준 (0.8 이상 권장)

### [지표 2] Semantic Similarity (코사인 유사도)
- **정의**: AI의 답변과 전문가의 모범 답안(Reference) 간의 의미적 유사성
- **측정 방법**:
  - OpenAI `text-embedding-3-small` 모델을 사용하여 두 문장을 벡터화
  - 두 벡터 사이의 코사인 유사도(Cosine Similarity) 계산 (0.0 ~ 1.0)
- **목표**: 모범 답안의 톤앤매너와 지식 수준을 얼마나 잘 따라 하는지 측정

### [지표 3] Hallucination Rate (환각 비율)
- **정의**: 답변 중 코드에 존재하지 않는 허구의 정보를 언급한 비율 (부정 지표)
- **측정 방법**:
  - 정규표현식 및 LLM-as-a-Judge를 활용하여 입력(Payload)에 없는 파일명/함수명/변수명 언급 횟수 카운트
- **목표**: 0%에 수렴하도록 관리

### [지표 4] LLM-as-a-Judge (정성적 정량화)
- **정의**: 상위 모델(GPT-4o 등)을 채점자로 활용하여 답변 품질을 1~10점으로 수치화
- **채점 항목**:
  - **정확성**: 기술적 원인을 정확히 짚었는가?
  - **중재안**: 해결 방법이 현실적이고 합리적인가?
  - **친절도**: 개발자가 이해하기 쉬운 용어를 사용했는가?

---

## 3. 평가 데이터셋 구성 (Evaluation Set)

평가 신뢰도를 높이기 위해 다음과 같이 데이터셋을 분리하여 관리합니다.

- **Golden Set (20개)**: 전문가가 직접 검수한 완벽한 정답이 포함된 데이터 (핵심 성능 측정용)
- **Synthetic Test Set (100개)**: 다양한 시나리오를 자동 생성한 데이터 (일반화 성능 측정용)

---

## 4. 성능 리포트 예시
학습 단계별로 다음과 같은 리포트를 산출하여 공유합니다.

| 단계 | Pass@1 | Similarity | Hallucination | Judge Score |
| :--- | :---: | :---: | :---: | :---: |
| Base Model | 0.45 | 0.62 | 15% | 5.2/10 |
| After SFT | 0.75 | 0.88 | 5% | 8.1/10 |
| After DPO | 0.85 | 0.92 | 1% | 9.0/10 |
