# GitCat 시연 시나리오

## 1. 문서 개요

본 문서는 GitCat 최종 시연 시 발표자가 화면 순서에 따라 기능을 시연할 수 있도록 작성한 실행 시나리오이다.

기준 문서:
- `docs/scenarios/04_test_demo_scenario.md`
- `docs/scenarios/04_test_demo_scenario.csv`
- `docs/scenarios/test/S-01.md` ~ `S-18.md`

## 2. 시연 전 준비

### 2.1 공통 준비

1. VS Code에서 GitCat 프로젝트 또는 데모용 Git 저장소를 연다.
2. GitCat extension이 활성화된 상태인지 확인한다.
3. Command Palette에서 `GitCat: Open Panel`을 실행해 패널이 열리는지 확인한다.
4. 데모에 사용할 브랜치와 변경 파일을 미리 준비한다.

### 2.2 `live-remote` 준비

1. `GMS_KEY`가 준비되어 있는지 확인한다.
2. `GMS_MODEL`, `GMS_BASE_URL` 설정값을 확인한다.
3. VS Code 설정에서 AI 모드가 `live-remote`인지 확인한다.

### 2.3 `live-local` 준비

1. GGUF 모델 파일이 로컬에 저장되어 있는지 확인한다.
2. `Gitcat > Ai: Local Model Path`가 올바른 절대 경로를 가리키는지 확인한다.
3. `GitCat: Install Local Runtime` 준비가 완료되었는지 확인한다.
4. VS Code 설정에서 AI 모드가 `live-local`인지 확인한다.

## 3. 시연 순서

### 3.1 패널 열기 및 기본 상태 확인

| 항목 | 내용 |
| --- | --- |
| 진입 메뉴 | Command Palette -> `GitCat: Open Panel` |
| 클릭 위치 | Command Palette 또는 GitCat 사이드바 아이콘 |
| 설명 포인트 | GitCat이 VS Code 내부에서 동작하는 로컬 실행형 도구임을 소개 |
| 기대 결과 | GitCat 패널이 정상적으로 열린다 |
| 실패 시 대체 흐름 | VSIX 재설치 또는 VS Code reload 후 다시 실행 |

### 3.2 스냅샷 생성 및 목록 확인

| 항목 | 내용 |
| --- | --- |
| 진입 메뉴 | GitCat 패널 또는 Command Palette |
| 클릭 위치 | `GitCat: Create Snapshot` 또는 스냅샷 생성 UI |
| 설명 포인트 | AI 작업 전 자동/수동 스냅샷으로 작업 유실을 방지 |
| 기대 결과 | 새 스냅샷이 생성되고 목록에 반영된다 |
| 실패 시 대체 흐름 | 저장소 상태 확인 후 수동 스냅샷 재실행 |

발표 멘트 예시:
- 변경 전 상태를 즉시 백업해 예기치 않은 작업 유실을 줄일 수 있음을 설명한다.
- 스냅샷 생성 속도와 그룹핑 여부를 함께 보여준다.

## 4. AI 모드별 시연 흐름

### 4.1 `live-remote`

1. VS Code 설정에서 AI 모드를 `live-remote`로 확인한다.
2. `GMS_KEY`, `GMS_MODEL`, `GMS_BASE_URL` 설정을 확인한다.
3. 추천 기능 또는 병합 분석을 실행한다.
4. 원격 AI 응답이 정상적으로 도착하는지 보여준다.

확인 포인트:
- 키가 없으면 입력 흐름이 발생하는지
- 결과가 패널에 정상 표시되는지
- 추천/분석 결과가 실제 UI 상태에 반영되는지

### 4.2 `live-local`

1. VS Code 설정에서 AI 모드를 `live-local`로 확인한다.
2. GGUF 파일 경로가 정확한지 보여준다.
3. 필요 시 `GitCat: Install Local Runtime` 준비 상태를 설명한다.
4. 동일한 추천 기능 또는 분석 기능을 실행한다.

확인 포인트:
- 로컬 모델 경로가 올바른지
- 로컬 런타임이 준비되었는지
- 외부 서버 없이 로컬에서 결과가 생성되는지

## 5. 최종 점검 체크리스트

- GitCat 패널이 정상적으로 열린다
- 스냅샷 생성이 동작한다
- 스냅샷 복원이 동작한다
- 병합 분석이 동작한다
- 충돌 후보 있음/없음 상태를 구분해 보여줄 수 있다
- `live-remote` 시연이 가능하다
- `live-local` 시연이 가능하다
- 추천 결과를 Accept/Reject/수정 반영으로 보여줄 수 있다
- 브랜치 정리 또는 GUI Git 기능을 보여줄 수 있다

## 6. 최종 제출 전 추가 기입 필요 정보

- 실제 발표 순서
- 실제 클릭 위치가 보이는 최신 UI 캡처
- `live-remote` 사용 시 실사용 모델명
- `live-local` 사용 시 실제 GGUF 파일명
- 시연 중 반드시 보여줄 핵심 기능 우선순위
